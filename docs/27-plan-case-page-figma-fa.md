# ۲۷ — برنامه: صفحهٔ پرونده هم‌راستا با Figma

**وضعیت:** فقط برنامه‌ریزی — هنوز مجوز پیاده‌سازی نیست.  
**تاریخ:** ۱۴۰۵/۰۸/۳۰  
**مرجع بصری:** Figma Design `wNPG51aOEQvnFBcHzreJ3u` (نمونه Make داخل فایل) + `tmp-make-flows/.../CaseDetail.tsx` مسیر `/cases/:id`.  
**قاعده:** ظاهر Make کپی نمی‌شود؛ توکن‌ها و کامپوننت‌های `web/` (Arte) مبناست. فلو و سلسله‌مراتب از Figma می‌آید.

## ۱. خواسته‌های مالک (به همان ترتیب)

1. صفحهٔ پرونده وقتی باز می‌شود، از نظر ساختار و سلسله‌مراتب شبیه طراحی Figma/Make باشد.  
2. دیزاین سیستم خود پروژه حفظ شود (نه تم کرم/نارنجی Make).  
3. قابلیت‌های فعلی پرونده (مرحله، چک‌لیست، پول، عکس، تاریخچه، اقدام بعدی) از بین نرود.

## ۲. وضعیت امروز

- فایل: `web/src/cases.tsx` — یک ستون موبایل، `status-line`، دکمهٔ اقدام بعدی، بخش‌های `Collapsible` / `details`.  
- Make: قهرمان پرونده (کد + وضعیت + وسیله + مشتری + تماس)، تب‌های نمای کلی / صورتحساب / تاریخچه، ریل اقدام بعدی + خلاصهٔ مالی، شیت اقدامات دیگر.  
- Figma Design فعلی بیشتر شِل خانه است؛ جزئیات پرونده از Make/`CaseDetail.tsx` خوانده می‌شود.

## ۳. پیشنهاد (پس از تأیید)

### ۳.۱ سلسله‌مراتب صفحه (موبایل‌اول)

1. **قهرمان:** `CASE-n`، متن وضعیت (`statusText`)، وسیله + پلاک، مشتری + دکمهٔ تماس.  
2. **اقدام بعدی:** یک دکمهٔ اصلی + «اقدام‌های دیگر» (BottomSheet فعلی).  
3. **خلاصهٔ مالی فشرده** (جمع / پرداخت / مانده) با ورود به بخش صورتحساب.  
4. **نمای کلی:** درخواست/نوع‌ها، چک‌لیست بازدید (با «انتخاب همه»)، ایرادها، عکس/فیلم، وضعیت بدنه.  
5. **صورتحساب / تاریخچه:** یا تب (مثل Make) یا همان بخش‌های تاشو — **سؤال باز A**.

### ۳.۲ قواعد محصول (بدون حدس)

- رنگ و فاصله از `--accent` / `--surface` / antislop.  
- تب فقط اگر روی موبایل شلوغی کم کند؛ وگرنه همان `details` نگه داشته شود.  
- هیچ API تازه‌ای لازم نیست مگر برای فیلد نمایشی که الان نیست.

### ۳.۳ داده / API

- همان `BuildDetail` فعلی.  
- بدون migration در فاز ۱.

### ۳.۴ تست

- رگرسیون دستی: اقدام بعدی، چک‌لیست، پرداخت، عکس، تاریخچه، تم روشن/تاریک، ۳۷۵px.  
- اگر تب اضافه شد: تست رندر و دسترسی صفحه.
