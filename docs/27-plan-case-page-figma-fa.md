# ۲۷ — برنامه: صفحهٔ پرونده هم‌راستا با Figma

**وضعیت:** فاز ۱ در main (PR #36). **فاز ۲+تب‌ها:** PR [#53](https://github.com/RezaHakimi1921/arte-service/pull/53) — مالک ۱۴۰۵/۰۹/۰۶ تصمیم A را عوض کرد: صفحه عین Make با سه تب؛ خسارت و رسید داخل صورتحساب؛ اقدام بعدی + خلاصه مالی بالای تب‌ها.  
**تاریخ:** ۱۴۰۵/۰۸/۳۰ (به‌روز: فاز ۲ با تب)  
**مرجع بصری:** Make و Design یک طراحی‌اند؛ مرجع فلو/سلسله‌مراتب: Make داخل فایل `wNPG51aOEQvnFBcHzreJ3u` + `tmp-make-flows/.../CaseDetail.tsx` مسیر `/cases/:id`.  
**قاعده:** ظاهر و رنگ Make کپی نمی‌شود؛ توکن‌ها و کامپوننت‌های `web/` (Arte) مبناست. فلو و سلسله‌مراتب از Make/CaseDetail می‌آید.

## ۱. خواسته‌های مالک (به همان ترتیب)

1. صفحهٔ پرونده وقتی باز می‌شود، از نظر ساختار و سلسله‌مراتب شبیه طراحی Figma/Make باشد.  
2. دیزاین سیستم خود پروژه حفظ شود (نه تم کرم/نارنجی Make).  
3. قابلیت‌های فعلی پرونده (مرحله، چک‌لیست، پول، عکس، تاریخچه، اقدام بعدی) از بین نرود.

## ۲. وضعیت امروز

- فایل: `web/src/cases.tsx` — یک ستون موبایل، `status-line`، دکمهٔ اقدام بعدی، بخش‌های `Collapsible` / `details`.  
- Make/CaseDetail: قهرمان پرونده (کد + وضعیت + وسیله + مشتری + تماس)، بخش‌های تاشو برای محتوا، ریل اقدام بعدی + خلاصهٔ مالی، شیت اقدامات دیگر.  
- فریم اختصاصی صفحهٔ پرونده در Design کامل نیست؛ Make و CaseDetail مرجع فعلی‌اند (و با Design هم‌خانواده‌اند).

## ۳. طرح تأییدشده (پیاده‌سازی فقط بعد از «شروع کن»)

### ۳.۱ سلسله‌مراتب صفحه (موبایل‌اول)

1. **قهرمان:** `CASE-n`، متن وضعیت (`statusText`)، وسیله + پلاک، مشتری + دکمهٔ تماس.  
2. **اقدام بعدی:** یک دکمهٔ اصلی + «اقدام‌های دیگر» (BottomSheet فعلی).  
3. **خلاصهٔ مالی فشرده** فقط برای نقش با مجوز پرداخت — وگرنه کل نوار پنهان (نه فقط بعضی فیلدها).  
4. **نمای کلی / صورتحساب / تاریخچه:** سه تب مثل Make (تصمیم تازهٔ مالک؛ جایگزین تاشوِ بدون تب).  
5. خسارت مشتری/زیان داخلی و رسیدهای مشتری داخل تب صورتحساب.

### ۳.۲ قواعد محصول (بدون حدس)

- رنگ و فاصله از `--accent` / `--surface` / antislop.  
- تب‌ها طبق Make؛ رنگ/فاصله فقط از Arte.  
- هیچ API تازه‌ای لازم نیست مگر برای فیلد نمایشی که الان نیست.

### ۳.۳ داده / API

- همان `BuildDetail` فعلی.  
- بدون migration در فاز ۱.

### ۳.۴ تست

- رگرسیون دستی: اقدام بعدی، چک‌لیست، پرداخت، عکس، تاریخچه، تم روشن/تاریک، ۳۷۵px.  
- نقش بدون مجوز پرداخت: هیچ مبلغ پرداخت/مانده (و چیزی که از آن بتوان پول را حدس زد) دیده نشود.
