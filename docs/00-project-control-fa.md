# ۰۰ — پنل راهبری پروژهٔ Arte Service

**نقش:** مرجع واحد برای «الان کجاییم و قدم بعدی چیست».  
**نیست:** جایگزین اسناد تخصصی، بک‌لاگ ایده‌ها، یا مجوز کدنویسی/merge/deploy.  
**قاعده:** پیشنهاد تأییدنشده را تصمیم قطعی ننویسید. ادغام‌شدن ≠ deployشدن.

**آخرین به‌روزرسانی این پنل:** ۱۴۰۵/۰۹/۰۴ (۲۰۲۶-۱۱-۲۵) — بررسی دستی پذیرش + پیشنهاد سند ۳۰  
**مبناى کد:** `origin/main` در `0f92eeb` (ادغام PR #41 ناوبری؛ پیش‌تر #40 docs، #39 فلو پذیرش)

### مسیر محصول پذیرش — اولویت اصلی و مرجع مسیر

هدف قطعی مطابق [سند ۲۸](28-intake-four-step-and-service-map-fa.md):

```text
مشتری و وسیله (یک صفحه) ← شرح پذیرش (کارت نوع → جزئیات) ← بازبینی (تخصیص و ثبت)
```

| واقعیت | وضعیت |
|---|---|
| هدف محصول | استپر بیرونی **سه‌مرحله‌ای** + زیرمرحلهٔ کارت→جزئیات |
| کد روی `main` | **پیاده شده** (PR #39) |
| Deploy production | **انجام و تأیید health** (#39 و بعداً #41 ناوبری) |
| بررسی دستی مالک | **انجام‌شده** (۱۴۰۵/۰۹/۰۴): ایراد بازدارنده‌ای دیده نشد — **نه** تأیید کامل همهٔ حالت‌ها/نقش‌ها/لبه‌ها |
| نگاشت خدمات | **تعویق D** — جدول وارد کد نشود |
| ظاهر | Design System Arte؛ Figma مرجع سلسله‌مراتب داخل شرح |
| ایراد در عیب‌یابی | ایراد اعلامی مشتری حفظ؛ جدا از تشخیص فنی |
| پیوست | شرط ثبت نیست؛ آپلود بعد از create |
| A — create | با `requestTypes` صریح، ایراد/خدمت/شرح اجباری نیست (در #39) |

**قدم بعدی (الان):** بازبینی و تأیید/اصلاح [پیشنهاد سند ۳۰](30-proposal-cancel-reopen-damage-fa.md) (لغو، بازگشایی، خسارت مستقل). تا پاسخ پرسش‌های باز و «شروع کن: …» کدی نزنید. نگاشت خدمات و صف پیامک همچنان نیازمند تصمیم جدا هستند.

## ۱. گردش وضعیت کار

| وضعیت | معنی |
|---|---|
| پیشنهاد | ایده یا طرح نوشته شده؛ مالک هنوز انتخاب نکرده |
| نیازمند تصمیم مالک | بدون پاسخ صریح مالک ادامه ممکن نیست |
| آمادهٔ اجرا | دامنه روشن؛ منتظر «شروع کن» |
| در حال انجام | کار فعال روی شاخه |
| PR برای بازبینی | PR باز؛ merge نشده |
| ادغام‌شده | روی `main`؛ هنوز ≠ deploy |
| deploy و تأییدشده | روی سرور + health پاس |

**ادغام ≠ deploy.**

## ۳. مسیر مرحله‌به‌مرحله (الان)

1. پنل را بخوانید (همین فایل).
2. پیشنهاد [۳۰](30-proposal-cancel-reopen-damage-fa.md) را بخوانید؛ به پرسش‌های باز پاسخ دهید یا «بعداً» بگویید.
3. برای برش بعدی: دامنه را با «شروع کن: …» باز کنید (نگاشت هنوز D است).
4. هر برش: تست → PR → merge → **سپس** deploy جدا → health.
5. بعد از هر تغییر معنی‌دار، بخش ۶–۷ این پنل را به‌روز کنید.

مرجع تفصیلی: [۲۴](24-implementation-roadmap-fa.md)، [۲۳](23-documentation-strategy-fa.md)، [۲۸](28-intake-four-step-and-service-map-fa.md)، [۳۰](30-proposal-cancel-reopen-damage-fa.md).
