### مسیر محصول پذیرش — اولویت اصلی و مرجع مسیر

هدف قطعی مطابق [سند ۲۸](28-intake-four-step-and-service-map-fa.md) (قفل ۱۴۰۵/۰۹/۰۴):

```text
مشتری و وسیله (یک صفحه) ← شرح پذیرش (کارت نوع → جزئیات وابسته) ← بازبینی (تخصیص و ثبت)
```

| واقعیت | وضعیت |
|---|---|
| هدف محصول | استپر بیرونی **سه‌مرحله‌ای** بالا + زیرمرحلهٔ کارت→جزئیات — **مرجع مسیر** |
| کد روی `main` | استپر ۳تایی هست؛ **کارت→جزئیات و فیلتر بلوک نوع هنوز نیست** |
| PR [#38](https://github.com/RezaHakimi1921/arte-service/pull/38) | **فقط مستندات**؛ پیاده‌سازی محسوب **نمی‌شود** |
| نگاشت خدمات | **تعویق D** — جدول وارد کد نشود؛ برش اول = فلو کارت→جزئیات |
| ظاهر | Design System Arte؛ Figma مرجع سلسله‌مراتب داخل شرح پذیرش (نه اجبار به جدا کردن مشتری/وسیله) |
| ایراد در عیب‌یابی | ایراد اعلامی مشتری حفظ؛ جدا از تشخیص فنی |
| پیوست | شرط ثبت نیست؛ آپلود بعد از create |

**قدم بعدی (الان):** مالک با پیام **«شروع کن: فلو پذیرش سند ۲۸ بدون نگاشت خدمات»** برش کد را باز کند. تا آن پیام فقط docs/merge #38.

## ۱. گردش وضعیت کار

هر کار فعال باید یکی از این وضعیت‌ها را داشته باشد. پرش بی‌شاهد ممنوع است.

| وضعیت | معنی |
|---|---|
| پیشنهاد | ایده یا طرح نوشته شده؛ مالک هنوز انتخاب نکرده |
| نیازمند تصمیم مالک | بدون پاسخ صریح مالک ادامه ممکن نیست |
| آمادهٔ اجرا | دامنه و معیار روشن است؛ منتظر «شروع کن» |
| در حال انجام | کدنویسی یا مستندسازی فعال روی شاخه |
| PR برای بازبینی | PR باز است؛ merge نشده |
| ادغام‌شده | روی `main` آمده؛ هنوز به معنی انتشار نیست |
| deploy و تأییدشده | روی سرور رفته و health/چک مورد توافق پاس شده |

**جداسازی اجباری:** «ادغام‌شده» به‌تنهایی «deploy و تأییدشده» نیست. تا health چک نشده، در پنل «روی سرور» ننویسید.

## ۳. مسیر مرحله‌به‌مرحله (الان)

1. **پنل را بخوانید** (همین فایل) → بلوک «مسیر محصول پذیرش» و کارهای فعال.
2. مرجع مسیر پذیرش را فقط از [۲۸](28-intake-four-step-and-service-map-fa.md) بگیرید؛ قواعد نوع/چک‌لیست از [۲۵](25-owner-decisions-intake-process-fa.md)؛ ترتیب پیشنهادی اجرا از [۲۹](29-proposal-intake-implementation-flow-fa.md) (**مصوب نیست**).
3. **تصمیم‌های قطعی** بخش ۴ را از پیشنهادهای باز بخش ۵ جدا نگه دارید؛ جدول نگاشت خدمات را قفل نکنید.
4. مالک تصمیم‌های باز را ببندد یا صریحاً به بعد موکول کند.
5. فقط پس از «شروع کن: فلو پذیرش سند ۲۸…» برش کوچک → تست → PR کد جدا → بازبینی → ادغام → **سپس** deploy جدا → health. ادغام #38 ≠ شروع کد.
6. بعد از هر تغییر معنی‌دار، بخش ۷ این پنل و جدول کارهای فعال به‌روز شود.

ترتیب تفصیلی مالک/تیم: [۲۴](24-implementation-roadmap-fa.md). مرجعیت اسناد: [۲۳](23-documentation-strategy-fa.md).
