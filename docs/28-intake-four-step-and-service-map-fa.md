# ۲۸ — فلو پذیرش و نگاشت پیشنهادی خدمت→نوع درخواست

**وضعیت:** تصمیم فلو (استپر بیرونی + کارت→جزئیات) **قطعی و مرجع مسیر محصول**؛ جدول نگاشت خدمات **فقط پیشنهادی** تا تأیید مالک.  
**اولویت / مرجع مسیر:**  
`مشتری و وسیله (یک صفحه) ← شرح پذیرش (کارت نوع → جزئیات وابسته) ← بازبینی (تخصیص و ثبت)`  
**بازبینی مالک ۱۴۰۵/۰۹/۰۴:** جدا کردن مشتری از وسیله در استپر بیرونی **لغو** شد؛ سه مرحلهٔ بالا قفل است. نام فایل تاریخی (`four-step`) عوض نشد تا لینک‌ها نشکند.  
**کد امروز:** استپر بیرونی سه‌مرحله‌ای هست، ولی زیرمرحلهٔ **کارت→جزئیات** و جزئیاتِ فقطِ نوع‌های انتخاب‌شده هنوز کامل نیست. PR #38 فقط docs است، پیاده‌سازی نیست.

روی `main` `84da1b9`:

- خدمات فقط با نوع وسیله؛ جدول بخش ۳ اعمال نشده (و نباید تا تأیید مالک).

## ۲. فلو هدف (قطعی برای مشخصات)

```text
[1 مشتری و وسیله] → [2 شرح پذیرش] → [3 بازبینی / تخصیص و ثبت]
                           │
                           ├─ 2a چهار کارت نوع (چندانتخابی) + ادامه
                           └─ 2b جزئیات فقط برای نوع‌های انتخاب‌شده
```

### مرحله ۱ — مشتری و وسیله (یک صفحه)
جستجوی مشتری (موبایل / پلاک)، مشتری جدید یا قبلی؛ سپس وسیلهٔ همان مشتری (موجود یا ثبت تازه). نوع وسیله طبق کسب‌وکار؛ جزئیات اختیاری (رنگ، VIN، …) جمع‌شونده تا صفحه شلوغ نشود. پلاک اختیاری.

### مرحله ۲ — شرح پذیرش
1. **کارت‌ها:** آچارکشی، عیب‌یابی، درخواست فنی/تعمیرات، سایر — چندانتخابی؛ حداقل یک نوع برای «ادامه». لمس کارت صفحه را عوض نمی‌کند.
2. **جزئیات (پس از ادامه):** فقط بلوک‌های مرتبط:
   - آچارکشی / تعمیرات: ایراد اعلامی مشتری (+ خدمات مرتبط فقط پس از تأیید نگاشت S1)
   - عیب‌یابی: **ایراد اعلامی مشتری حفظ**؛ نتیجهٔ فنی/`Diagnosis` اینجا ثبت نمی‌شود (بعد از ایجاد پرونده)
   - سایر: شرح آزاد + پیوست اختیاری؛ بدون چک‌لیست اجباری
3. عکس/فیلم در جزئیات قابل انتخاب بماند؛ آپلود بعد از create؛ شرط ثبت نیست.

### مرحله ۳ — بازبینی
خلاصهٔ مشتری، وسیله، نوع‌ها، جزئیات، تعداد رسانه؛ **اختصاص مسئول**؛ تیک پیامک پذیرش؛ سوخت/بدنهٔ اختیاری؛ ثبت پرونده.

### ۳.۳ قواعد پیشنهادی برای اعمال جدول (تا تأیید)

1. فیلتر نهایی نمایش خدمت = **اشتراک** (نوع وسیله ∩ اتحاد نوع‌های انتخاب‌شده).  
2. خدمتی که فقط O دارد، فقط وقتی «سایر» انتخاب شده دیده شود.  
3. خدمت با چند نوع پیشنهادی، اگر هر کدام از آن نوع‌ها انتخاب شده باشد دیده شود.  
4. ردیف‌های «؟» تا پاسخ مالک در UI اعمال نشوند (یا موقتاً فقط زیر نوع محتمل‌تر با برچسب «مبهم» در سند بمانند — نه در کد).

## ۵. اختلاف با اسناد قبلی (خلاصه)

| قبل | بعد (این سند — قفل ۱۴۰۵/۰۹/۰۴) |

| نسخهٔ میانی همین سند: ۴ استپر بیرونی (مشتری جدا از وسیله) | استپر بیرونی **۳**تایی؛ مشتری و وسیله **یک صفحه** |
| Make چهار استپر بیرونی به‌عنوان هدف محصول | Make/Figma مرجع **داخل شرح پذیرش** (کارت→جزئیات)؛ نه اجبار به جدا کردن مشتری/وسیله |
| شرح پذیرش = یک صفحهٔ تخت | شرح پذیرش = **کارت‌ها سپس جزئیات** با دکمهٔ ادامه |
| خدمات فقط بر اساس نوع وسیله | هدف: وسیله + نوع درخواست؛ جدول بخش ۳ در انتظار تأیید |

تصمیم‌های حفظ‌شده: چهار کلید نوع، جدایی ایراد/خدمت/تشخیص، ایراد اعلامی در عیب‌یابی، چک‌لیست سروری، پیوست شرط ثبت نیست، ثبت پرونده پیش از تکمیل چک‌لیست.
