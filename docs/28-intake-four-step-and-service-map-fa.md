## ۱. قطعی در برابر در انتظار تأیید

### ۱.۱ قطعی (مالک تأیید کرده — حفظ شود)

| موضوع | تصمیم |
|---|---|
| چهار نوع سطح‌بالا | `wrenching` آچارکشی · `diagnosis` عیب‌یابی · `repair` درخواست فنی/تعمیرات · `other` سایر |
| چندنوع در یک پرونده | مجاز |
| تعویض چرخ | زیر «سایر»، نه نوع سطح‌بالا |
| ایراد اعلامی مشتری | جدا از خدمات درخواستی و جدا از تشخیص تعمیرکار |
| ایراد اعلامی | برای آچارکشی و تعمیرات قابل ثبت؛ نتیجهٔ فنی عیب‌یابی روی پرونده پس از ثبت |
| چک‌لیست | فقط برای سه نوع اول در صورت نگاشت تنظیمات؛ «سایر» بدون چک‌لیست اجباری |
| زمان چک‌لیست | پس از ثبت پرونده روی صفحهٔ پرونده؛ ناقص‌بودن مانع ایجاد پرونده نیست، مانع شروع کار است |
| نگاشت چک‌لیست | سمت سرور (`RequestTypeChecklistBinding`) — از قبل پیاده شده |
| پیش‌نویس، برگشت مراحل، عکس/فیلم، مسئول، خلاصهٔ بازبینی | حفظ |
| استپر بیرونی پذیرش | **چهار مرحله:** مشتری ← وسیله ← شرح پذیرش ← بازبینی |
| داخل «شرح پذیرش» | ابتدا **چهار کارت** چندانتخابی؛ انتخاب کارت **خودکار** به صفحهٔ بعد نمی‌رود؛ با «ادامه» وارد **جزئیات** نوع‌های انتخاب‌شده می‌شود |
| جزئیات | فقط بخش‌های مربوط به نوع‌های انتخاب‌شده |
| «سایر» در جزئیات | شرح آزاد + پیوست؛ بدون چک‌لیست اجباری |

### ۱.۲ در انتظار تأیید مالک (حدس نزن / قطعی نکن)

| # | موضوع | وضعیت |
|---|---|---|
| S1 | جدول نگاشت هر خدمت کاتالوگ فعلی → نوع(ها) | **پیشنهادی** در بخش ۳؛ تا تأیید شما قفل نشود |
| S2 | شکل فنی نگاشت (فقط UI، جدول سرور، ترکیبی، یا تعویق) | باز؛ گزینه‌ها در بخش ۴ |
| S3 | آیا یک خدمت می‌تواند هم‌زمان زیر چند نوع باشد؟ | پیشنهاد پیش‌فرض: بله (چند ستون در جدول) — تأیید لازم |
| S4 | پیوست «سایر»: همان عکس/فیلم پذیرش کافی است یا پیوست جدا؟ | باز |
| S5 | وقتی چند نوع انتخاب شده، خدمات مشترک چگونه ادغام/برچسب می‌شوند؟ | باز (پیشنهاد: اتحاد فهرست‌ها بدون تکرار عنوان) |
| S6 | خدمات سفارشی tenant (`custom.serviceCategories`) چگونه به نوع وصل شوند؟ | باز |

### ۱.۳ وضعیت کد امروز (واقعیت، نه هدف)

- `web/src/intake.tsx`: استپر **۳**تایی (مشتری+وسیله با هم → شرح پذیرش یک‌صفحه → بازبینی).
- انواع درخواست: چیپ روی همان صفحهٔ ایراد/خدمت/عکس؛ پرش خودکار ندارد، ولی **زیرمرحلهٔ کارت→جزئیات** جدا نیست.
- خدمات: فقط با **نوع وسیله** (`serviceCategoriesFor`)؛ بدون نگاشت نوع‌درخواست.

## ۲. فلو هدف (قطعی برای مشخصات)

```text
[1 مشتری] → [2 وسیله] → [3 شرح پذیرش] → [4 بازبینی]
                              │
                              ├─ 3a چهار کارت (چندانتخابی) + ادامه
                              └─ 3b جزئیات فقط برای نوع‌های انتخاب‌شده
```

### مرحله ۱ — مشتری
جستجو با موبایل (و پلاک در صورت نیاز)، مشتری جدید/قبلی، حداقل فیلدهای ضروری.

### مرحله ۲ — وسیله
انتخاب وسیلهٔ موجود یا ثبت تازه؛ نوع وسیله طبق تنظیمات کسب‌وکار؛ جزئیات اختیاری جمع‌شونده.

### مرحله ۳ — شرح پذیرش
1. **کارت‌ها:** آچارکشی، عیب‌یابی، درخواست فنی/تعمیرات، سایر — چندانتخابی؛ حداقل یک نوع برای «ادامه».
2. **جزئیات (پس از ادامه):** فقط بلوک‌های مرتبط، مثلاً:
   - آچارکشی / تعمیرات: ایراد اعلامی (+ در صورت تأیید نگاشت: خدمات مرتبط)
   - عیب‌یابی: طبق قواعد قبلی، تمرکز بر مسیر تشخیص پس از ثبت؛ خدمات نگاشت‌شده فقط پس از تأیید S1
   - سایر: شرح آزاد + پیوست؛ بدون چک‌لیست اجباری
3. عکس/فیلم پذیرش در این مرحله (یا زیرمرحلهٔ جزئیات) قابل دسترسی بماند — قابلیت فعلی حفظ شود.

### مرحله ۴ — بازبینی
خلاصهٔ مشتری، وسیله، نوع‌ها، جزئیات، رسانه؛ مسئول پرونده؛ پیامک پذیرش؛ وضعیت سوخت/بدنهٔ اختیاری؛ ثبت پرونده.

### ۳.۳ قواعد پیشنهادی برای اعمال جدول (تا تأیید)

1. فیلتر نهایی نمایش خدمت = **اشتراک** (نوع وسیله ∩ اتحاد نوع‌های انتخاب‌شده).  
2. خدمتی که فقط O دارد، فقط وقتی «سایر» انتخاب شده دیده شود.  
3. خدمت با چند نوع پیشنهادی، اگر هر کدام از آن نوع‌ها انتخاب شده باشد دیده شود.  
4. ردیف‌های «؟» تا پاسخ مالک در UI اعمال نشوند (یا موقتاً فقط زیر نوع محتمل‌تر با برچسب «مبهم» در سند بمانند — نه در کد).

## ۵. اختلاف با اسناد قبلی (خلاصه)

| قبل | بعد (این سند) |
|---|---|
| فلو محصول = ۳ مرحله (مشتری+وسیله با هم) | فلو محصول = **۴** مرحله (مشتری جدا از وسیله) |
| Make چهارمرحله‌ای «پذیرفته‌نشده» / الهام صرف | Make/Figma مرجع **فلو و سلسله‌مراتب** استپر |

| سند ۲۵ قرارداد: گاهی «۲ مرحله» در جدول Make | منسوخ؛ به این سند ارجاع شود |

تصمیم‌های حفظ‌شده: چهار کلید نوع، جدایی ایراد/خدمت/تشخیص، چک‌لیست سروری، سایر بدون چک‌لیست اجباری، ثبت پرونده پیش از تکمیل چک‌لیست.

1. مالک جدول بخش ۳ (و ردیف‌های ؟) را تأیید یا اصلاح کند.  
2. مالک گزینهٔ بخش ۴ (A–D) را انتخاب کند.  
3. سپس با پیام صریح «شروع کن: فلو چهارمرحله‌ای پذیرش [+ نگاشت خدمات در صورت تأیید]» برش کد روی شاخهٔ جدا آغاز شود.
